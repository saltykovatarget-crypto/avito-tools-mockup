## ⚖️ КЛЮЧЕВОЕ ЮРИДИЧЕСКОЕ РЕШЕНИЕ (обязательно к прочтению)

**Деньги на балансе пользователя = авансовый платёж за услуги (ст. 487 ГК РФ).**

Это **не электронные деньги** (161-ФЗ не применяется, лицензия ЦБ не нужна).

### Что это значит для бэка:

| Зона | Правило |

| **В UI** | Слово «Кошелёк» / «Баланс» (привычно юзеру) |

| **Что НЕЛЬЗЯ делать** (превратит в ЭДС → потребует лицензию ЦБ) | ❌ Перевод средств между юзерами<br>❌ Свободный вывод на карту (только возврат по обращению в поддержку)<br>❌ Использование баланса вне сервиса |

## ❌ Почему НЕ начинать с UI

1. **UI без бэкенда = декорация**. Невозможно зарегистрировать пользователя, принять платёж, ответить AI, запустить парсер. То есть и показать клиенту нечего, и тестировать невозможно.

2. **Бэк диктует контракт API**, фронт под него подстраивается. Если сделать UI первым, потом всё придётся переписывать (как именно баланс приходит, какие поля у транзакции, как обрабатывается 402 и т.д.).

3. **Тонкие места живут в бэке**:
   - Идемпотентность платежей (вебхук Точки может прилететь дважды)
   - Атомарность списания (`with_for_update` на балансе)
   - Race conditions (юзер шлёт 2 сообщения подряд)
   - Webhook signature verification
   - Возвраты, отмены, refund
   - Кэш сессий, авторизация по JWT

   Это всё фундамент. Если он шатается — UI бесполезен.

4. **Я (Лера) могу одновременно докручивать UI**, пока ты строишь бэк. К моменту когда бэк готов, UI уже подключается за пару дней.

**Почему вторым:** без денег сервис не работает. Кошелёк — сердце wallet-модели.

### Phase 3 — AI Чат + GPT-5.1 (3–4 дня)

- [ ] Сервис чата:
  - Хранение диалогов (`chats`, `messages` таблицы)
  - SSE (Server-Sent Events) или WebSocket для стрима ответа AI
  - Интеграция с GPT-5.1 API
  - Prompt caching (для экономии 70% на cache hits)
- [ ] **Интеграция с кошельком**:
  - Перед запросом к GPT → `WalletService.spend_pending(CHAT_MESSAGE)`
  - Если успех → `confirm_pending`
  - Если ошибка GPT → `cancel_pending` (деньги возвращаются)
- [ ] Endpoint `POST /api/chat/messages`:
  - Body: `{chat_id, content}`
  - Возвращает stream с токенами
  - HTTP 402 если недостаточно средств → фронт открывает модалку пополнения
- [ ] Endpoint `POST /api/messages/{id}/thumb-down` — тихий сигнал

**Почему третьим:** это core ценность продукта. После этого юзер может реально пользоваться.

## ⚠️ Важное про деньги (юридическое)

- **Не сжигать деньги**: остатки на кошельке — это депонированные средства, не доход. Доход = только списание за услугу.
- **54-ФЗ**: чек надо выдавать **при списании за услугу** (а не при пополнении). Так делают все цифровые сервисы. Уточни с бухгалтером или юристом.
- **Возвраты**: только через поддержку, по запросу. Без 60-дневного срока не нужно делать (Лера решает по ситуации).
- **152-ФЗ** (персональные данные): Telegram даёт минимальный набор (id, имя, username). Достаточно для регистрации.
