## 📨 Прямой ответ Точки

> 🔷 Для формирования разовых платежей c формированием кассового чека можно использовать метод API **Create Payment Operation With Receipt**:
> https://developers.tochka.com/docs/tochka-api/api/create-payment-operation-with-receipt-acquiring-api-version-payments-with-receipt-post
>
> Сейчас у вас подключён интернет-эквайринг с сервисом фискализации **"Чеки"**, поэтому при таком методе чеки будут успешно формироваться.
>
> 🔷 Что касается **произвольной суммы**: Как таковую именно многоразовую ссылку через API не сделать, только если покупатель будет указывать эту произвольную сумму в интерфейсе клиента и клиент будет передавать её в запросе.
>
> 🔷 **Точка Чеки подходят только для полной оплаты**, то есть при работе с авансами вам необходимо либо в интернет-банке выбрать облачную кассу, с которой уже есть готовая интеграция, либо другую облачную кассу, но настраивать интеграцию с ней на своей стороне.

## 🎯 Что это значит для архитектуры

### ✅ Что уже OK

| Что | Решение |
|---|---|
| **Разовые платежи** | Используем `Create Payment Operation With Receipt` |
| **Произвольная сумма** | Фронт уже передаёт сумму при создании платежа (TopupModal.tsx) |
| **Эквайринг** | Уже подключён, фискализация «Чеки» работает |

### ⚠️ Ключевой нюанс

**Точка Чеки = только полная оплата.** В wallet-модели у нас аванс:
1. Юзер пополняет кошелёк (например, +500 ₽) → **чек «Аванс»**
2. Юзер тратит из кошелька (например, −5 ₽ за ответ AI) → **чек «Зачёт аванса»**

→ **Точка Чеки не выдаёт чек "Зачёт аванса"** для второго случая.

### 🔧 Решение

Архитектура **двухслойная**:

```
[Платежи РУБ]               [Чеки 54-ФЗ]
─────────────               ─────────────
Точка Банк              →   Точка Чеки (для оплаты услуги полностью)
эквайринг                   
                        
                            Облачная касса (для аванса/зачёта аванса)
                            ⬆ ↑
                            Лера выбирает из готовых интеграций
                            в интернет-банке Точки
                            ИЛИ
                            подключаем стороннюю (АТОЛ Онлайн / ОФД.ру)
```

**Точка делает только эквайринг** (списание денег с карты юзера). Чеки идут через **облачную кассу** (отдельный сервис).

### Иван делает

#### A. Эквайринг (Точка) — создание платежей

```python
# При создании платежа в /api/wallet/topup:
POST https://api.tochka.com/api/v1/acquiring/payments-with-receipt
Authorization: Bearer <TOCHKA_TOKEN>
{
  "customer_id": "user_<our_user_id>",
  "amount": 39000,  # копейки (390 ₽ — пакет)
  "purpose": "Пополнение кошелька AI Авитолог PRO",
  "redirect_url": "https://aiavitologpro.ru/wallet/success",
  "fail_url": "https://aiavitologpro.ru/wallet/fail",
  "client_info": {
    "email": "<user_email>",
    "phone": "<user_phone>"
  },
  "receipt": {
    # ВАЖНО: Точка чеки выдадут «Полная оплата».
    # Нам нужен «Аванс» → используем облачную кассу (см. ниже)
    # Если в этом методе Точки можно поставить признак расчёта="Аванс" — используем.
    # Если нет — отключаем receipt здесь и выдаём отдельно через облачную кассу
  }
}
```

**Важно проверить в документации Точки**: можно ли в `Create Payment Operation With Receipt` указать признак расчёта «Аванс»? Если можно — обходимся без второй кассы для пополнений. Чек «Зачёт аванса» при списании всё равно нужен через облачную кассу.

#### B. Webhook от Точки → обновление баланса

```python
@app.post("/api/webhooks/tochka")
async def tochka_webhook(payload: TochkaWebhook):
    # 1. Проверка подписи (HMAC)
    verify_signature(payload, signature_header)
    
    # 2. Idempotency — не обработать повторно
    if already_processed(payload.payment_id):
        return {"ok": True}
    
    # 3. Увеличить advance_payment_kopecks юзера
    with db.transaction():
        user = db.query(User).filter_by(id=payload.user_id).with_for_update().first()
        user.advance_payment_kopecks += payload.amount_kopecks
        
        db.add(WalletTransaction(
            user_id=user.id,
            type='topup',
            amount_kopecks=payload.amount_kopecks,
            idempotency_key=f"tochka:{payload.payment_id}",
            external_payment_id=payload.payment_id,
        ))
    
    # 4. Выдать чек "Аванс" через облачную кассу (если Точка не сделала)
    await cloud_kassa.issue_receipt(
        payment_method='advance',  # признак расчёта = аванс
        amount=payload.amount_kopecks,
        user_email=user.email,
        user_phone=user.phone,
        item_name='Пополнение кошелька AI Авитолог PRO',
    )
```

        """
        ...

**Что вызывается когда:**

| Событие | payment_method | item_name |
|---|---|---|
| Пополнение кошелька | `advance` | «Пополнение кошелька AI Авитолог PRO» |
| Списание 5 ₽ за ответ AI | `advance_offset` | «Ответ AI Авитолога» |

## 🔍 Открытые технические вопросы

### Вопрос 1 — Точка может «Аванс»?

Иван должен проверить в документации Точки:
- В методе `Create Payment Operation With Receipt` есть параметр для **признака расчёта**?
- Если да и он поддерживает «Аванс» → пополнения чекуем через Точку, экономим на облачной кассе
- Если нет → пополнения тоже через облачную кассу (как и списания)

📎 Дока: https://developers.tochka.com/docs/tochka-api/api/create-payment-operation-with-receipt-acquiring-api-version-payments-with-receipt-post

### Вопрос 2 — какая облачная касса лучше?

После того как Лера посмотрит в интернет-банке Точки готовые интеграции — выберем по критериям:
- Цена за чек (обычно 1–5 ₽)
- Лимит чеков в месяц
- Простота API
- Скорость выдачи (нужно <2 сек)

Если у Точки нет приоритетной готовой интеграции — кандидаты:
- **АТОЛ Онлайн** — самый популярный, дорогой, надёжный
- **ОФД.ру** — дешевле, проще
- **Бизнес.ру** — простой API
- **МойСклад Облачная касса** — если есть аккаунт

### Вопрос 3 — fallback если касса упала?

Что делать если облачная касса вернёт ошибку при выдаче чека?

**Рекомендация**: класть в очередь retry. Чек **должен** быть выдан по 54-ФЗ в течение **24 часов**. Если за 24 часа не получилось — алёрт в админку, Лера разбирается руками.

```python
# При ошибке выдачи чека
receipt_queue.enqueue(
    user_id=user.id,
    transaction_id=tx.id,
    payment_method='advance',
    retry_after=now() + 30s,
    max_retries=20,  # каждые 30с → 60с → 120с → ... до 24 часов
)
```

## 🚨 Что обязательно по 54-ФЗ (не пропустить)

- Чек выдаётся **в течение 24 часов** с момента расчёта
- Чек содержит: ФИО юзера или его email/телефон, наименование услуги, сумму, признак расчёта, ИНН ИП, дату/время
- Все чеки уходят в **ОФД** автоматически (через облачную кассу)
- Юзер должен получить **электронный чек** на email или sms
