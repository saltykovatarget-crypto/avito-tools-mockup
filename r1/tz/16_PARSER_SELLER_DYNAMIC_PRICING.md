# Парсер конкретного продавца — тарифная сетка по объёму

**Дата:** 2026-06-03 (финальное решение)
**Статус:** идея на R2 / после запуска R1
**Связано:** `15_PARSER_VISION_ARCHITECTURE.md`, `01_parser_integration.md`

> ⚠️ **ВАЖНО:** Это **отдельный новый инструмент** — «Парсер продавца».
>
> Существующий «Парсер ниши / выдачи» (190 ₽ фикс / 200 объявлений в выдаче / vision на всех) **остаётся как есть** — не трогаем.

## 🎯 Главное решение

**Тарифная сетка с минимумом 90 ₽** и снижением цены за объявление при росте объёма (опт):

| Объём продавца | Цена | За объявление | Выгода клиенту |
|---|---|---|---|
| **до 50 объявлений** | **90 ₽** | 1.8 ₽ | минимум |
| **51-100** | **150 ₽** | 1.5 ₽ | — |
| **101-200** | **300 ₽** | 1.5 ₽ | — |
| **201-500** | **500 ₽** | 1.0 ₽ | дешевле на 33% |
| **501-1500** | **1 000 ₽** | 0.67 ₽ | дешевле на 55% |
| **1501-5000** | **2 000 ₽** | 0.4 ₽ | дешевле на 78% |

**Принцип**: чем больше объявлений у продавца, тем дешевле клиенту за единицу. SaaS-логика «опт» — выгодно для тяжёлых случаев.

**Потолок: 5 000 объявлений** (физический лимит Авито + 1-3 часа парсить не имеет смысла).

## 🔧 Как это работает для юзера

### Шаг 1 — Pre-check (бесплатно)

Юзер вводит URL продавца → бэк парсит **только страницу профиля** (не все объявления) → возвращает:
- Имя продавца
- Сколько у него объявлений
- Рейтинг / отзывы
- **Рассчитанную цену** для парсинга

### Шаг 2 — Подтверждение

AI в чате показывает:

```
🔍 Продавец DoorHanRu

📊 247 активных объявлений
⭐ 4.9 (59 отзывов)

Тариф: 201-500 объявлений → 500 ₽

Это разбор всех 247 объявлений: фото с vision-анализом,
тексты, цены, динамика просмотров, паттерны.

Запустить? [Да за 500 ₽] [Нет]
```

Юзер нажимает → списание 500 ₽ → парсер стартует.

**Психология ценника**: юзер видит «501-1500 объявлений → 1 000 ₽» и понимает, что **за двойной объём платит всего вдвое больше** (а не в 5 раз). Это создаёт ощущение опт-скидки.

### Шаг 3 — Парсинг

См. таблицу таймингов:

| Объём | Время | Vision-стратегия |
|---|---|---|
| До 300 | 5-20 мин | Vision на всех |
| 300-1000 | 30-60 мин | Vision на топ-300 по просмотрам |
| 1000-5000 | 1-3 часа | Vision на топ-300 по просмотрам |

**Vision на топ-300** для больших объёмов — крупные продавцы имеют длинный хвост мёртвых объявлений, их анализировать бессмысленно. Берём 300 самых живых.

## 🛠 Технически для Ивана

### Pre-check endpoint

```
GET /api/parser/seller/precheck?url=<seller_url>
→ {
    "seller_name": "DoorHanRu",
    "seller_id": "...",
    "ads_count": 247,
    "rating": 4.9,
    "reviews": 59,
    "tier_label": "201-500",
    "price_kopecks": 50000,           // 500 ₽
    "estimated_time_min": 20
  }
```

Стоимость самого pre-check — **бесплатно** для юзера (1-2 секунды, копейки на бэкенде).

### Запуск парсинга

```
POST /api/parser/seller/start
Body: {
  "seller_url": "...",
  "confirmed_price_kopecks": 50000  // защита от подмены цены
}
→ списание + старт задачи
```

Если за время между pre-check и start у продавца появились новые объявления и он перешёл в **следующий тариф** → используем **зафиксированную** цену (`confirmed_price_kopecks`), чтобы юзер не получил неожиданный счёт.

### Vision-стратегия по объёму

```python
VISION_LIMIT = 300

def get_vision_strategy(ads_count: int):
    if ads_count <= VISION_LIMIT:
        return {"mode": "all", "limit": None}
    return {"mode": "top_by_views", "limit": VISION_LIMIT}
```

При парсинге сначала собираем все объявления (текст + URL фото), затем сортируем по `views_today` desc и берём топ-300 для vision.

### Расчёт цены на бэкенде

```python
def compute_seller_price_kopecks(ads_count: int) -> int | None:
    """Тарифная сетка с минимумом 90 ₽ и опт-скидкой за объём."""
    if ads_count <= 50:    return 9_000     # 90 ₽
    if ads_count <= 100:   return 15_000    # 150 ₽
    if ads_count <= 200:   return 30_000    # 300 ₽
    if ads_count <= 500:   return 50_000    # 500 ₽
    if ads_count <= 1500:  return 100_000   # 1 000 ₽
    if ads_count <= 5000:  return 200_000   # 2 000 ₽
    return None  # > 5000 — не парсим
```

## 🎯 Где это в продуктовом roadmap

**Не в R1.** Добавляем в R2 (после запуска базовой версии с парсером ниши).

Технически парсер продавца **в 3 раза проще** парсера ниши:
- Парсер ниши: ходить по выдаче, ротация, market_share, агрегаты по 44 продавцам
- Парсер продавца: один URL → его объявления (та же логика парсинга, но проще)

Если парсер ниши уже работает → парсер продавца делается за **2-3 дня**.

| Параметр | Парсер ниши | Парсер продавца |
|---|---|---|
| Цена | 190 ₽ (фикс) | Тарифная сетка 90 / 150 / 300 / 500 / 1 000 / 2 000 ₽ |
