# Парсер конкретного продавца — динамическое ценообразование

**Дата:** 2026-06-03 (решение Леры)
**Статус:** идея на R2 / после запуска R1
**Связано:** `15_PARSER_VISION_ARCHITECTURE.md`, `01_parser_integration.md`

---

## 🎯 Главное решение

**Цена парсера продавца = 50 ₽ (базовая) + 1 ₽ × количество объявлений у продавца**

| Объявлений | Цена | Себестоимость | Маржа |
|---|---|---|---|
| 10 | 60 ₽ | ~15 ₽ | 75% |
| 50 | 100 ₽ | ~35 ₽ | 65% |
| 100 | 150 ₽ | ~60 ₽ | 60% |
| 200 | 250 ₽ | ~110 ₽ | 56% |
| 500 | 550 ₽ | ~265 ₽ | 52% |
| 1000 | 1 050 ₽ | ~530 ₽ | 50% |

Маржа стабильно 50-75%, независимо от объёма.

**Потолок: 5 000 объявлений** (физический лимит — Авито показывает не больше + 4-8 часов парсить не имеет смысла).

---

## ⚠️ Почему фиксированная цена 90 ₽ не работает

| Объём | Vision-стоимость | Парсинг | Себестоимость при 90 ₽ |
|---|---|---|---|
| 50 объявлений | ~25 ₽ | ~5 ₽ | маржа 60 ₽ (67%) ✅ |
| 200 объявлений | ~100 ₽ | ~10 ₽ | маржа −20 ₽ ❌ убыток |
| 500 объявлений | ~250 ₽ | ~20 ₽ | маржа −180 ₽ ❌ катастрофа |
| 5 000 объявлений | ~2 500 ₽ | ~50 ₽ | маржа −2 460 ₽ ❌❌❌ |

При фиксе нельзя нормально работать с крупными продавцами.

## 🔧 Как это работает для юзера

### Шаг 1 — Pre-check (бесплатно)

Юзер вводит URL продавца → бэк парсит **только страницу профиля** (не все объявления) → возвращает:
- Имя продавца
- Сколько у него объявлений
- Рейтинг / отзывы
- **Рассчитанную цену** для парсинга

### Шаг 2 — Подтверждение

AI в чате показывает:

```
🔍 Продавец DoorHanRu

📊 247 активных объявлений
⭐ 4.9 (59 отзывов)

Парсинг — 297 ₽
Это разбор всех 247 объявлений: фото с vision-анализом,
тексты, цены, динамика просмотров, паттерны.

Запустить? [Да за 297 ₽] [Нет]
```

Юзер нажимает → списание 297 ₽ → парсер стартует.

### Шаг 3 — Парсинг

См. таблицу таймингов:

| Объём | Время | Vision-стратегия |
|---|---|---|
| До 100 | 5-10 мин | Vision на всех |
| 100-500 | 15-30 мин | Vision на всех |
| 500-1000 | 30-60 мин | Vision на топ-100 по просмотрам |
| 1000-5000 | 1-3 часа | Vision на топ-100 по просмотрам |

**Vision на топ-100** для больших объёмов — крупные продавцы имеют длинный хвост мёртвых объявлений, их анализировать бессмысленно. Берём 100 самых живых.

## 🛠 Технически для Ивана

### Pre-check endpoint

```
GET /api/parser/seller/precheck?url=<seller_url>
→ {
    "seller_name": "DoorHanRu",
    "seller_id": "...",
    "ads_count": 247,
    "rating": 4.9,
    "reviews": 59,
    "estimated_price_kopecks": 29700,
    "estimated_time_min": 20
  }
```

Стоимость самого pre-check — **бесплатно** для юзера (1-2 секунды, копейки на бэкенде).

### Запуск парсинга

```
POST /api/parser/seller/start
Body: {
  "seller_url": "...",
  "confirmed_price_kopecks": 29700  // защита от подмены цены
}
→ списание + старт задачи
```

Если за время между pre-check и start у продавца появились новые объявления → используем **зафиксированную** цену (`confirmed_price_kopecks`), чтобы юзер не получил неожиданный счёт.

### Vision-стратегия по объёму

```python
def get_vision_strategy(ads_count: int):
    if ads_count <= 500:
        return {"mode": "all", "limit": None}
    else:
        return {"mode": "top_by_views", "limit": 100}
```

При парсинге сначала собираем все объявления (текст + URL фото), затем сортируем по `views_today` desc и берём топ-100 для vision.

### Расчёт цены на бэкенде

```python
def compute_seller_price_kopecks(ads_count: int) -> int:
    BASE = 5000        # 50 ₽
    PER_AD = 100       # 1 ₽
    MAX_ADS = 5000
    
    effective = min(ads_count, MAX_ADS)
    return BASE + effective * PER_AD
```

## 🎯 Где это в продуктовом roadmap

**Не в R1.** Добавляем в R2 (после запуска базовой версии с парсером ниши).

Технически парсер продавца **в 3 раза проще** парсера ниши:
- Парсер ниши: ходить по выдаче, ротация, market_share, агрегаты по 44 продавцам
- Парсер продавца: один URL → его объявления (та же логика парсинга, но проще)

Если парсер ниши уже работает → парсер продавца делается за **2-3 дня**.

## 🆚 Сравнение с парсером ниши

| Параметр | Парсер ниши | Парсер продавца |
|---|---|---|
| Цена | 190 ₽ (фикс) | 50 + 1×N ₽ (динамика) |
| Что анализирует | Топ-100 в выдаче | Все объявления одного продавца |
| Vision | На всех 100 | На всех / на топ-100 (если >500) |
| Доля рынка | Считаем | Не нужна |
| Позиции в выдаче | Важны | Не важны (один продавец) |
| Use case | «Какая ниша, кто в топе» | «Как работает конкретный лидер» |
| Сложность бэка | Высокая | Низкая (после ниши) |
